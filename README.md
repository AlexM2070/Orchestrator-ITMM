# Orchestrator-ITMM
Репозиторий команды 3, для разработки оркестратора по кейсу №2

## MVP Оркестратора Бизнес-Процессов

Учебный проект по реализации централизованного локального оркестратора пайплайнов данных на Python. Система управляет потоками данных и координирует работу двух расчетных микросервисов:
1. **`rr_calc`** — Оперативный расчет пруденциального рыночного риска (2 источника, 5 таблиц).
2. **`krs_load`** — Расчет контрагентской кредитной экспозиции / КРС (4 источника, 10 таблиц).

---

## Основные возможности MVP
* **Сквозная трассировка (Data Lineage):** Генерация уникального идентификатора (`Process ID` на базе `uuid4`) при каждом запуске для отслеживания всех этапов прохождения данных.
* **Локальное хранилище (CSV):** Имитация баз данных источников через строгую иерархию папок с CSV-файлами.
* **Быстрый ETL-пайплайн:** Чтение, фильтрация и объединение (`merge` / `concat`) таблиц в оперативной памяти с помощью библиотеки `pandas`.
* **Графический Дашборд (UI):** Современный темный интерфейс на базе `CustomTkinter` с выводом логов выполнения в реальном времени и отображением финального сводного отчета.

## Установка и запуск

Для работы проекта требуется установленный **Python 3.10+**.

### 1. Клонирование репозитория
```bash
git clone <URL_вашего_репозитория>
cd my_orchestrator
```

### 2. Создание и активация виртуального окружения (Рекомендуется)
* **Для Windows (PowerShell):**
  ```powershell
  python -m venv .venv
  .venv\Scripts\Activate.ps1
  ```
  *(Если возникает ошибка прав доступа в PowerShell, выполните: `Set-ExecutionPolicy Unrestricted -Scope Process`)*

* **Для Windows (CMD):**
  ```cmd
  python -m venv .venv
  .venv\Scripts\activate.bat
  ```

* **Для macOS / Linux:**
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  ```

### 3. Установка зависимостей
Установите необходимые библиотеки (`pandas` и `customtkinter`) из файла конфигурации:
```bash
pip install -r requirements.txt
```
*(Если команда `pip` не распознается, используйте: `python -m pip install -r requirements.txt`)*

### 4. Запуск приложения
```bash
python main.py
```

## Сценарий тестирования и демонстрации

Чтобы продемонстрировать работу, выполните следующие шаги:

1. Запустите программу (`python main.py`) и нажмите кнопку **«Запустить сквозной процесс»**.
2. Обратите внимание на сгенерированный `Process ID`, логи загрузки таблиц и итоговые суммы в отчете.
3. Закройте окно приложения.
4. Откройте любой исходный CSV-файл в папке `data/` (например, через Excel или блокнот) и измените несколько числовых значений или удалите пару строк. Сохраните файл.
5. Снова запустите `python main.py` и нажмите кнопку запуска.
6. Система сгенерирует **новый `Process ID`**, перечитает обновленные файлы и выведет **пересчитанный результат**.

## Распределение ролей в команде и контракты

Разработка ведется параллельно по методологии **Contract-Driven Development**. Каждый участник отвечает за свой изолированный модуль:

| Роль | Зона ответственности (Файлы) | Контракт (Вход -> Выход) |
| :--- | :--- | :--- |
| **Участник 1**<br>*Data Engineer* | Папка `data/` | Очистка данных от мусорных значений, формирование строгой структуры папок и CSV. |
| **Участник 2**<br>*Data Loader* | `src/data_loader.py` | `load_service_data(service_name: str) -> dict[str, pd.DataFrame]` |
| **Участник 3**<br>*ETL Developer 1* | `src/service_rr.py` | `process_rr_calc(process_id: str, tables: dict) -> tuple[pd.DataFrame, list[str]]` |
| **Участник 4**<br>*ETL Developer 2* | `src/service_krs.py` | `process_krs_load(process_id: str, tables: dict) -> tuple[pd.DataFrame, list[str]]` |
| **Участник 5**<br>*Frontend / UI* | `src/dashboard.py` | Класс `OrchestratorUI`. Методы `append_log(msg: str)` и `show_result_table(df: pd.DataFrame)`. |
| **Участник 6**<br>*Team Lead / Core* | `main.py`, Git | Генерация `uuid`, сборка всех модулей в единый пайплайн `run_pipeline()`, разрешение конфликтов в Git. |

### Важные правила для разработчиков:
1. **Не меняйте названия функций и типы возвращаемых данных** (контракты) без согласования с командой, иначе сломается сборка в `main.py`.
2. **Не переименовывайте папки и CSV-файлы** в директории `data/` без согласования с командой.
3. Перед отправкой кода в репозиторий (`git push`) убедитесь, что вы не добавляете лишние файлы (папки `.venv/`, `__pycache__/`, `.idea/`, `.vscode/` уже внесены в `.gitignore`).
